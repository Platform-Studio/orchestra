# Product Development Handoffs

Read the task, attachments, comments, audit history, workstream context, and repository instructions before acting.

Before every state change, add a normal task comment that records what was done, relevant evidence, remaining risks, and why the next lane owns the work. A failed review or test must state the problem, impact, required correction, and verification steps.

Use `Blocked` only when work cannot continue. The blocker comment must name the blocker, next action, likely owner, and lane to resume. Humans retain control of prioritization, consequential product decisions, credentials, approvals, and interventions.
